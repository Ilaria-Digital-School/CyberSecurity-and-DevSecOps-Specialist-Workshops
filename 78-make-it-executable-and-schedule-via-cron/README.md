# Make it executable and schedule via cron

THEORETICAL RECAP A Bash script is just a text file until you grant it execute permission and provide an interpreter. The shebang line (#!/bin/bash) on the first line tells the system which interpreter to use. Permissions are managed with chmod: chmod +x script.sh adds the execute bit. Think of it this way: the file must be readable AND executable by the user who runs it, and the shebang must point to a valid interpreter path. A common mistake is running a script with 'sh script.sh' when it uses Bash-specific syntax, which silently breaks features. cron is the Linux scheduler that runs commands automatically at fixed times. Each user has a crontab (edited with 'crontab -e'). A cron line has five time fields followed by the command: minute hour day-of-month month day-of-week. For example, '0 2 * * * /home/user/backup.sh' runs the script every day at 02:00. The mental model: cron wakes up every minute, compares the current time to each line, and fires matching jobs. Common mistakes: using relative paths (cron runs with a minimal environment and a different working directory), forgetting that cron has almost no PATH, and not redirecting output (cron mails output by default, which you rarely see). Always use absolute paths, define variables explicitly, and redirect stdout/stderr to a log file. Mini example: '*/15 * * * * /usr/bin/find /tmp -type f -mtime +7 -delete >> /var/log/cleanup.log 2>&1'.
