# Digital chmod 755/644

**Theoretical Recap** Linux permissions are expressed numerically using an octal (base-8) system. Each file or directory has three permission groups: owner (user), group, and others. Each group is assigned a value based on three binary bits: read (r = 4), write (w = 2), and execute (x = 1). Adding these values together gives the octal digit for each group. For example, rwx = 4+2+1 = 7, r-x = 4+0+1 = 5, and r-- = 4+0+0 = 4. The two most commonly used permission sets in secure Linux environments are 755 and 644. chmod 755 (rwxr-xr-x) means the owner can read, write, and execute, while the group and others can only read and execute — typical for directories and executable scripts. chmod 644 (rw-r--r--) means the owner can read and write, while the group and others can only read — typical for configuration files and static content. A common mistake is applying 777 permissions out of convenience, which grants full access to everyone and opens serious security vulnerabilities. Another frequent error is confusing file and directory permissions: a directory needs execute permission for users to enter it (cd), even if they do not need to run any program inside it. Mini example: a web server's HTML files should be 644 (readable by the server process, writable only by the owner), while the directories containing them should be 755 (traversable by all, but not writable by the public).
