# Run commands and read their help

Theoretical Recap: The Interface of Power You have explored the operating system's role and the Linux terminal. This workshop now focuses on the fundamental skill of commanding the system. A command is a direct instruction you give to the system via the terminal. It follows a standard structure: the command name itself, options (or flags) that modify its behavior, and arguments, which are the targets or data the command acts upon. A clear mental model is crucial. Think of the terminal as a conversation with the operating system's kernel. You type a request, and the system executes a corresponding program to fulfill it. The help system, built into most commands, is your built-in manual, not a sign of weakness. A common beginner mistake is to memorize commands without understanding their options or to ignore error messages, which are often precise guides to what went wrong. Consider the numeric example of listing files. Typing `ls` is the basic command. Adding the `-l` option changes the output to a detailed, long list format. Combining it with `-h` (`ls -lh`) makes file sizes human-readable. The order of options typically doesn't matter (`ls -hl` works the same), but arguments, like a directory name (`ls -lh /home`), usually come last. Brief and Initial Exploration Your task is to move from passive knowledge to active control by running commands, interpreting their output, and using their built-in documentation to solve problems.
