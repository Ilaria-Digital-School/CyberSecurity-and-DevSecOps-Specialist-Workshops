# Write a /etc backup script

THEORETICAL RECAP The /etc directory is the heart of Linux system configuration. It contains critical files: user accounts (/etc/passwd, /etc/shadow), network settings, service configurations, firewall rules, and repository definitions you manipulated in earlier lessons. Losing or corrupting /etc can render a system unbootable or insecure, which is why backing it up is a foundational security and DevSecOps practice. The mental model is simple: a backup script is an automated routine that copies a source (here /etc) into a compressed, timestamped archive stored in a safe location, ideally with integrity verification and log output. Think of it as a repeatable, deterministic snapshot you can restore from at any moment. You already know the Bash building blocks: variables, loops, and conditions. A minimal example combines them with the tar command: #!/bin/bash SRC="/etc" DEST="/var/backups" STAMP=$(date +%Y%m%d-%H%M%S) tar -czf "$DEST/etc-$STAMP.tar.gz" "$SRC" Common mistakes to avoid: running the script without root privileges (many /etc files are unreadable to normal users), forgetting to check whether the destination directory exists, hardcoding paths without variables, ignoring error codes, and never testing the restore. A backup you cannot restore is worthless. Always verify exit status ($?) after critical commands and confirm your archive is not empty or truncated.
