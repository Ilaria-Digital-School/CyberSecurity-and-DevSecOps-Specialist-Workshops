# Symbolic chmod step by step

**Theoretical Recap** File permissions in Linux are a foundational security mechanism. Every file and directory has three permission sets: owner (u), group (g), and others (o). Each set can carry three types of permissions: read (r), write (w), and execute (x). The chmod command modifies these permissions, and its symbolic mode uses a human-readable syntax: [who][operator][permissions]. The 'who' part is u, g, o, or a (all). The operator is + (add), - (remove), or = (set exactly). For example, chmod g+w file.txt adds write permission to the group, while chmod o-rx script.sh removes read and execute from others. A common mental model: think of permissions as a security gate. The owner controls their own gate, the group shares a second gate, and others face a third. chmod is the key-maker. Common mistakes include confusing u (user/owner) with a (all), forgetting that directories need execute permission to be entered, and inadvertently opening permissions to others when using chmod a+. Remember: in a security context, the principle of least privilege means granting only the minimum permissions necessary. Never add permissions 'just in case.' Also note that chmod does not change ownership — that is chown's job, which you will encounter separately.
