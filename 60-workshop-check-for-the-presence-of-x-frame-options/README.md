# Workshop: check for the presence of X-Frame-Options

**Theoretical Recap** The X-Frame-Options HTTP response header is a security mechanism that instructs the browser whether or not a web page can be embedded inside an , , , or element. It is a first line of defense against Clickjacking attacks, where an attacker overlays an invisible malicious frame on top of a legitimate page to trick users into clicking on hidden elements. The header accepts three values: DENY (the page cannot be framed at all), SAMEORIGIN (the page can only be framed by pages from the same origin), and ALLOW-FROM uri (deprecated and not supported in modern browsers). When this header is absent, the target page is potentially vulnerable to Clickjacking. A common mistake is to confuse X-Frame-Options with the Content-Security-Policy frame-ancestors directive, which is its modern successor and takes precedence when both are present. Another frequent error is checking only the status code of an HTTP response without actually reading the headers dictionary. Keep in mind that a server may return a 200 OK with no security headers at all. For example, using the Requests library: response = requests.get('https://example.com'); print(response.headers.get('X-Frame-Options', 'ABSENT')).
