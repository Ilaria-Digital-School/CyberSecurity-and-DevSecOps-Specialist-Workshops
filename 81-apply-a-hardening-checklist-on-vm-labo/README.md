# Apply a hardening checklist on VM labo

## Project Overview In this mini-project, you will apply a complete security hardening checklist to a Linux virtual machine (VM) in a lab environment. This project consolidates every skill covered in the 'Linux advanced for security' chapter: user and sudoer management, permissions, scripting, cron scheduling, logging and auditing, and hardening principles (CIS Benchmarks, attack surface minimization). You will start from a fresh, deliberately non-hardened Linux VM and transform it into a hardened system that follows recognized industry standards. You will document each step, automate what can be automated, prove that each control is effective, and measure your progress with an audit tool. ## Context and Scenario You have been hired as a junior security engineer. Your team provisions Linux servers for production but delivers them with default configurations. Your task is to define and apply a reproducible hardening baseline on a lab VM before it can be promoted to a controlled environment. Management wants evidence: a before/after audit score, a documented checklist, and automation scripts that guarantee the configuration can be reapplied identically. ## Scope - Target: one Linux VM (Debian/Ubuntu or CentOS/Rocky) that you control in your lab. - You must NOT operate on any system outside your authorized lab perimeter. - Hardening domains to cover: user/account security, SSH hardening, sudo/privilege management, filesystem and permissions, service and package minimization, network exposure, logging/auditing/log rotation, and automated scheduled checks. ## Why this matters Hardening is the practical foundation of defensive security and DevSecOps.
