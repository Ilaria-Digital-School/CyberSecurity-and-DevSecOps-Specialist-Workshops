# Getting started with OWASP Threat Dragon on the Blog project

THEORETICAL RECAP Threat modeling is the structured practice of identifying, communicating, and understanding threats and mitigations within the context of protecting an application. OWASP Threat Dragon is a free, open-source tool that lets you draw Data Flow Diagrams (DFDs) and attach threats to each element using the STRIDE mental model. The core mental model is simple: an application is a set of components (external entities, processes, data stores) connected by data flows, all separated by trust boundaries. Every time data crosses a trust boundary, risk appears. STRIDE gives you six lenses to inspect each element: Spoofing (identity), Tampering (integrity), Repudiation (accountability), Information Disclosure (confidentiality), Denial of Service (availability), and Elevation of Privilege (authorization). A common beginner mistake is drawing a diagram that is too detailed or too shallow: aim for a level where each process and data store maps to a real security decision. Another frequent error is forgetting trust boundaries entirely, which makes STRIDE analysis meaningless. A mini example: for a Blog login form, the flow 'User -> Web App' crosses a trust boundary; STRIDE flags Spoofing (weak auth), Tampering (no HTTPS), and Elevation of Privilege (broken access control). Each threat then gets a risk rating and a proposed mitigation, connecting directly to the checklist and test-plan work you completed in previous activities.
