# Securing a shared folder

**Theoretical Recap** In Linux, a shared folder is a directory accessed by multiple users or groups simultaneously. Securing it correctly means applying the right combination of ownership, permissions, and special bits to ensure that only authorized users can read, write, or execute files within it — and that they cannot interfere with each other's work unless explicitly allowed. Key definitions you must internalize: **owner** (the user who created the file or directory), **group** (a set of users sharing common access rights), and **others** (everyone else). Permissions are expressed as read (r=4), write (w=2), and execute (x=1) for each of these three categories. The **chmod** command modifies these permissions (symbolically or digitally), while **chown** and **chgrp** change ownership and group assignment respectively. Two special permission bits are critical for shared folders: the **SetGID bit** (chmod g+s) forces new files created inside the directory to inherit the group of the directory rather than the creator's primary group — essential for collaboration. The **Sticky bit** (chmod +t) prevents users from deleting files they do not own, even if they have write access to the directory — this is exactly how /tmp works. Common mistakes include setting permissions too broadly (777 on sensitive directories), forgetting to apply SetGID so files end up owned by random groups, and omitting the sticky bit so users can delete each other's files.
