# Locate assets in a “Todo List” application

THEORETICAL RECAP In threat modeling, an 'asset' is anything of value that an attacker might want to steal, alter, destroy, or misuse — and that you must therefore protect. Assets are not only files or databases; they include data (user credentials, task content, session tokens), functionality (the ability to create or delete tasks, authentication), and infrastructure components (the API, the database, secrets, configuration). A useful mental model is to ask three questions for every part of the application: 'What is valuable here?', 'Who would want it?', and 'What happens if it is compromised (confidentiality, integrity, availability)?'. Remember the vocabulary from your previous lessons: an asset is what you protect, a threat is what can harm it, a vulnerability is the weakness that lets a threat succeed, and risk combines the likelihood and impact. A common beginner mistake is to list only obvious technical components (like 'the server') while ignoring the data itself, or to confuse an asset with a vulnerability. Another mistake is stopping at the surface and forgetting hidden assets such as JWT secrets, environment variables, or backup files. Mini example: in a Todo List app, the 'user's task list' is a data asset. Its confidentiality matters (another user should not read it), its integrity matters (no one should silently modify it), and its availability matters (the owner must always access it).
