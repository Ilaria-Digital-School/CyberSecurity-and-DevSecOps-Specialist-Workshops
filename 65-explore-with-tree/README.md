# Explore with tree

THEORETICAL RECAP The `tree` command is a Linux utility that recursively displays the directory structure of a filesystem path in a visual, hierarchical format — much like a branching diagram. Unlike `ls`, which only lists the immediate contents of a directory, `tree` gives you the full picture of nested subdirectories and files at a glance. This makes it an essential reconnaissance tool in security contexts, where understanding the layout of a system, a web application, or a deployment directory can reveal misplaced sensitive files, overly permissive structures, or unexpected configuration exposure. Key concepts to keep in mind: `tree` outputs directory depth (controllable with `-L `), can display hidden files (`-a`), can filter by file type (`-d` for directories only), and can output results in formats like JSON or XML for further parsing. A common mistake beginners make is running `tree` without any depth limit on large filesystems — this can produce thousands of lines of output and is inefficient. Always scope your exploration. Another pitfall is forgetting that `tree` may not be installed by default; use `sudo apt install tree` if needed. A quick mental model: think of `tree` as a map-maker — before you explore unknown territory, you draw the map first. Mini example: running `tree -L 2 /var/www/html` will display the web server root directory up to two levels deep, immediately revealing whether configuration files, backup files, or sensitive folders are exposed — a classic first step in a web pentest reconnaissance phase.
