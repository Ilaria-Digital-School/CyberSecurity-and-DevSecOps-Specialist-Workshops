# Workshop: Setting the number of ping packets

**Theoretical Recap** In the previous workshop, you built a Python script that executes the `ping` command using the `subprocess` library and saves the output to a file. That script worked, but it used a hardcoded, default number of packets — meaning you had no control over how many ICMP requests were sent. In network reconnaissance and security auditing, controlling the packet count matters: too few packets may yield unreliable results, while too many can trigger IDS/IPS alerts or saturate a network link. The `subprocess.run()` function accepts a list of arguments that maps directly to a command-line call. For example, `subprocess.run(['ping', '-c', '4', '192.168.1.1'])` on Linux/macOS sends exactly 4 packets. On Windows, the equivalent flag is `-n`. This means your script must detect the operating system at runtime — the `platform` or `sys` module can help here — and adapt the flag accordingly. A common mistake is hardcoding the packet count as a string directly in the script without validating user input, which can lead to runtime errors or, worse, command injection risks if the value comes from an untrusted source. Always validate that the input is a positive integer before passing it to `subprocess`. Another frequent error is forgetting that `subprocess.run()` arguments must all be strings, not integers — always cast your count with `str()`. Mini example: `count = str(int(user_input))` followed by `subprocess.run(['ping', '-c', count, target])` is the correct and safe pattern. --- **Workshop Brief** This workshop builds directly on the previous one.
