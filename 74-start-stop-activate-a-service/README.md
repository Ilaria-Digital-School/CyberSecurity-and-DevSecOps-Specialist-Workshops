# Start, stop, activate a service

THEORETICAL RECAP On modern Linux systems, systemd is the init system and service manager (PID 1). A 'service' is a unit described by a unit file (usually ending in .service) located under /lib/systemd/system/ or /etc/systemd/system/. The core mental model is to distinguish two independent concepts: the RUNTIME STATE (is the service running right now?) and the BOOT STATE (will it start automatically at next boot?). You control the runtime state with 'systemctl start', 'systemctl stop', and 'systemctl restart', and you control the boot state with 'systemctl enable' and 'systemctl disable'. These are orthogonal: a service can be running but disabled, or stopped but enabled. Use 'systemctl status ' to inspect the current state, the main PID, and recent log lines, and 'journalctl -u ' to read the full journal of that unit. A common beginner mistake is confusing 'enable' with 'start': running 'enable' does NOT launch the service immediately (use 'enable --now' to do both). Another mistake is forgetting 'systemctl daemon-reload' after editing a unit file. Security-wise, an unnecessary enabled service widens the attack surface, so knowing how to reliably stop and disable services matters. Mini example: 'sudo systemctl start ssh' starts SSH now; 'sudo systemctl enable ssh' makes it persist across reboots; 'systemctl is-active ssh' and 'systemctl is-enabled ssh' confirm each state separately.
