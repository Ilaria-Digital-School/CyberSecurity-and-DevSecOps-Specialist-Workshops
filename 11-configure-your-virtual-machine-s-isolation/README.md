# Configure your virtual machine's isolation

Theoretical Recap You have learned that isolation is the practice of separating one computing environment from another to prevent unwanted interactions. In virtualization, isolation means your virtual machine operates independent of your host machine and network. Key concepts include network isolation, where a virtual machine cannot see your real network, and host isolation, where actions inside the virtual machine cannot affect your host computer's files or operating system. A mental model to remember is the airlock. An airlock maintains a seal between two environments. Your isolated virtual machine should be sealed from your personal and professional digital environments. This ensures any training, testing, or analysis conducted inside the lab cannot leak out, and external threats cannot unexpectedly get in during your exercises. It creates a controlled, safe sandbox. A common mistake is confusing convenience for security. While a NAT network allows a virtual machine internet access, it provides less isolation than a true internal or host-only network. Another mistake is failing to use snapshots before configuring isolation settings. This makes recovery from misconfiguration difficult. Always take a new snapshot before modifying network or host settings. A mini example: Imagine your host has IP address 192.168.1.100 on your home Wi-Fi. You configure your virtual machine's network adapter for 'Internal Network' mode. The virtual machine will get an IP like 192.168.100.10, but this network 192.168.100.0/24 exists only between your host and its virtual machines.
