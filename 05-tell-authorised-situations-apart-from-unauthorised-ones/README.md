# Tell authorised situations apart from unauthorised ones

Theoretical Recap This workshop builds directly on your recent lessons about ethical boundaries and the legal framework. The core principle is that authorisation is the single factor separating ethical security testing from criminal intrusion. You must internalise a clear mental model: any interaction with a computer system is unauthorised unless you have explicit, written permission from the system owner. Key definitions are essential. Authorisation is formal, documented consent granting you specific permissions on defined systems for a set period. Scope defines the precise boundaries of this authorisation—which systems, networks, and types of tests are included. Unauthorised access is any action exceeding this scope or performed without this consent, which is illegal under laws like the Computer Fraud and Abuse Act (CFAA) in the US or the Computer Misuse Act in the UK. A common mistake is assuming implied authorisation. Owning a device, having a user account, or being employed by a company does not automatically grant permission for security testing. Another error is scope creep, where testing expands beyond agreed boundaries because a related system seems interesting. A mini example: you have authorisation to test a company's external website. Finding a connected internal server and probing it constitutes unauthorised access, even if the vulnerability is glaring. Your mental model must be binary: authorised or not. There is no grey area in legality. This workshop will challenge you to apply this binary model to complex, realistic scenarios, reinforcing that intent is irrelevant without the proper paperwork.
