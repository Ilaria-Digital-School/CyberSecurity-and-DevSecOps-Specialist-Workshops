# Adapting the principles to a file upload microservice

THEORETICAL RECAP Secure design principles are not abstract rules; they are decision filters you apply to concrete features. Least Privilege means every component (service account, container, database user, storage bucket) holds only the permissions strictly required for its task, and nothing more. Defense in Depth means you never rely on a single control: if one layer fails, another still protects the asset. The CIA triad (Confidentiality, Integrity, Availability) defines what you are protecting, while STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) helps you enumerate what can go wrong at each element of a Data Flow Diagram (DFD). A useful mental model: picture a file upload as a hostile input crossing a trust boundary. Everything before validation is untrusted. Your job is to shrink the blast radius at every hop — client, API gateway, upload service, storage, and any downstream processing (antivirus, image resizing, indexing). Common mistakes: trusting the client-declared Content-Type, storing files inside the web root, giving the upload service full read/write access to the entire storage account, and running file parsers with elevated privileges. Mini example: an app accepts 'invoice.pdf' but only checks the extension. An attacker uploads 'shell.pdf' containing PHP code, and because files land in a web-executable directory, requesting the URL runs the code — a direct Elevation of Privilege caused by a missing validation layer and a violation of Least Privilege on the storage location.
