# Chown and chgrp

THEORETICAL RECAP In Linux, every file and directory has two ownership attributes: a user owner and a group owner. These are distinct from permissions (which you have already practiced with chmod), but they work hand in hand: permissions only mean something in relation to who owns the resource. `chown` (change owner) allows you to modify the user owner of a file or directory, and optionally its group owner in a single command: `chown user:group file`. `chgrp` (change group) is more focused: it changes only the group owner. Both commands require elevated privileges (sudo or root) to reassign ownership to another user. A critical mental model: think of ownership as the identity layer and permissions as the access layer. You can give a file read/write permissions to its owner, but if the wrong user owns the file, those permissions protect the wrong person. This is a classic misconfiguration in security contexts. Common mistakes: - Forgetting sudo when reassigning ownership to a different user - Confusing `chown user file` (changes user owner only) with `chown user:group file` (changes both) - Using `chgrp` when the user is not a member of the target group - Applying changes non-recursively on directories when recursive behavior is needed (`-R` flag) Mini example: `sudo chown www-data:www-data /var/www/html/index.html` assigns the file to the web server user and group, a typical DevSecOps configuration to prevent privilege escalation on web servers. --- WORKSHOP BRIEF This workshop places you in the role of a junior Linux system administrator preparing a secure...
