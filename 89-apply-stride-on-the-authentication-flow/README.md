# Apply STRIDE on the authentication flow

THEORETICAL RECAP STRIDE is a threat classification model created by Microsoft that maps six threat categories to the security properties they violate: Spoofing (breaks Authentication), Tampering (breaks Integrity), Repudiation (breaks Non-repudiation), Information Disclosure (breaks Confidentiality), Denial of Service (breaks Availability), and Elevation of Privilege (breaks Authorization). The mental model is simple: you take a system decomposed into components and data flows, then, for each element crossing a trust boundary, you ask 'Can each of the six STRIDE threats happen here?'. A trust boundary is any point where data or control passes between zones of different privilege (for example, browser to server, or server to database). An authentication flow is a prime target because it directly handles identity and secrets. A minimal flow includes: a user submitting credentials, a login endpoint, a credential store, a session/token issuer, and the returned session cookie or JWT. Mini example: at the 'submit credentials' step, Spoofing appears as credential stuffing or reusing stolen passwords; Information Disclosure appears if credentials travel over plain HTTP. Common mistakes: confusing the attacker (the actor) with the threat (the technique), listing generic threats without tying them to a specific data flow or boundary, forgetting Repudiation because it feels abstract, and mixing STRIDE (finding threats) with mitigation (fixing them) too early.
