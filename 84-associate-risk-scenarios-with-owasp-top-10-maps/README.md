# Associate risk scenarios with OWASP Top 10 (maps)

THEORETICAL RECAP The OWASP Top 10 is a consensus-based, regularly updated list of the ten most critical web application security risks. It is not a checklist of individual bugs but a set of risk categories, each grouping many concrete weaknesses. The current categories include A01 Broken Access Control, A02 Cryptographic Failures, A03 Injection, A04 Insecure Design, A05 Security Misconfiguration, A06 Vulnerable and Outdated Components, A07 Identification and Authentication Failures, A08 Software and Data Integrity Failures, A09 Security Logging and Monitoring Failures, and A10 Server-Side Request Forgery. Mental model: a risk scenario describes how an actor/attacker exploits a vulnerability against an asset, producing an impact on Confidentiality, Integrity, or Availability (CIA). Mapping to OWASP means answering: 'Which category best describes the root cause of this scenario?' Reuse the vocabulary from earlier lessons — asset, threat, vulnerability, risk — and the actor/attacker distinction. Common mistakes: confusing the symptom with the root cause (e.g., mapping stolen data to A02 when the real cause is missing authorization = A01); forcing every scenario into A03 Injection; ignoring that one scenario may touch several categories but usually has one dominant root cause. Mini example: 'A user changes the id in the URL /todo?id=42 to /todo?id=43 and reads another user's tasks.' Asset: user tasks (Confidentiality impact). Root cause: missing ownership check → A01 Broken Access Control.
