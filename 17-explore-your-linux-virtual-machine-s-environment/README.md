# Explore your Linux virtual machine's environment

Theoretical Recap To properly explore a Linux environment, you must first solidify your mental model of its architecture. You have encountered the operating system's role as the conductor and the system's main components: kernel, programs, and users. A helpful mental model is to view Linux as a layered system. At the core is the kernel, managing hardware and providing system calls. Around it resides the shell, your command-line interpreter. Finally, user-space applications and the graphical interface complete the system. Key definitions include the shell, a program providing an interface to the operating system's services, and terminal, a program that runs a shell. The other key concept is the file system hierarchy, a single tree-like structure starting from the root directory (/). Common mistakes involve confusing similar commands, like `ls` for listing files and `less` for viewing them, or misunderstanding case sensitivity. Beginners often get lost in the file system without using `pwd` to print their current location. A small numeric example: The command `ls -l` lists files with detailed information. The output shows columns like permissions (e.g., -rw-r--r--), the number of links (like 1), owner name, group name, file size in bytes (e.g., 1024), timestamp, and filename. The size '1024' represents one kibibyte of data, a concrete measure of a file's footprint.
