# Identify open interfaces and ports

THEORETICAL RECAP A network interface is a connection point between your machine and a network. On Linux, interfaces such as 'lo' (loopback, 127.0.0.1), 'eth0' or 'enp0s3' (wired), and 'wlan0' (wireless) each carry one or more IP addresses. A port is a 16-bit number (0-65535) that identifies a specific service listening on an interface. A socket is the combination of an IP address and a port, plus a protocol (TCP or UDP). The mental model to keep: an address answers 'which machine?', a port answers 'which service on that machine?'. A listening socket bound to 0.0.0.0 is reachable from every interface; one bound to 127.0.0.1 is reachable only locally. This distinction is central in security: an SSH daemon exposed on 0.0.0.0:22 is an attack surface, the same daemon on 127.0.0.1:22 is not. Common mistakes: confusing an established connection with a listening service; assuming a closed firewall means no listening process; and ignoring UDP because it is stateless and harder to observe. Mini example: run 'ss -tlnp' and you might see 'LISTEN 0 128 0.0.0.0:22'. This tells you sshd is listening on all interfaces on TCP port 22. Change it to '127.0.0.1:22' and the exposure disappears from the external network. Mapping interfaces to listening ports is the first recon step of any audit.
