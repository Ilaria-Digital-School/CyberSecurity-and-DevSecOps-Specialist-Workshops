# Install your first training target in the isolated lab

Theory recap: Training targets and isolation You have built an isolated virtual machine lab. A training target is a deliberately vulnerable software application or operating system designed for security practice. Its core purpose is to provide a safe, legal environment to test attacks without harming real systems. Think of it as a digital shooting range where every bullet hole is expected and welcomed for learning. The mental model for this workshop is a layered containment system. Your host computer runs the virtualization software. Inside it, your isolated Linux virtual machine acts as the primary lab environment. Within that VM, you will install and run the training target application. This creates three security boundaries between your practice and the real world. A common mistake is confusing isolation with immunity. While your network-isolated VM cannot initiate contact with your home network, files can still be transferred via the virtualization software's shared folder features if configured. Another error is assuming all training targets are equally complex; some require specific database backends or web servers to function properly. A small numeric example illustrates the architecture. Your host machine might have IP address 192.168.1.100. Your isolated VM, with no network bridge, has no IP address or uses a completely internal one like 172.16.0.10, unreachable from your host. The training target, once installed inside the VM, might listen on port 80 (HTTP) or 8080, only accessible from within the VM itself.
