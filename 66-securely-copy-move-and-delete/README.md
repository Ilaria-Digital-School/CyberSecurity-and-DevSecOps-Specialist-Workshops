# Securely copy, move, and delete

THEORETICAL RECAP In Linux, copying, moving, and deleting files are everyday operations — but in a security context, each action carries real risk. The commands cp, mv, and rm are powerful and unforgiving: there is no Recycle Bin, no undo, and no prompt by default. Understanding how to use them safely is not optional for a cybersecurity professional. cp copies a file or directory from a source to a destination. Without the -r flag, it cannot copy directories. The -p flag preserves permissions and timestamps — critical when copying sensitive files whose metadata must be maintained for forensic or audit purposes. mv moves or renames a file. It is atomic on the same filesystem, meaning it either succeeds completely or not at all — a property that matters when handling logs or evidence files. rm permanently deletes files. The -r flag removes directories recursively. The -i flag prompts before each deletion. Never run rm -rf on an unknown or variable path — a classic and catastrophic mistake. Tools like shred or wipe exist specifically to overwrite file content before deletion, preventing recovery — essential when handling credentials, keys, or sensitive data. Common mistakes include: overwriting a destination file without realizing it, deleting the wrong directory due to a typo or an unquoted variable, and assuming deleted files are unrecoverable (they are not, without secure deletion).
