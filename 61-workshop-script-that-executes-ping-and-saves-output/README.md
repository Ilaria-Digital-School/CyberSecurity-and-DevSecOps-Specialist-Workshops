# Workshop: script that executes 'ping' and saves output

**Theoretical Recap** The `subprocess` module is Python's standard way to launch system commands from a script. It replaces the older `os.system()` approach and gives you fine-grained control over the process: you can capture stdout and stderr, pass arguments safely, handle return codes, and set timeouts. The two most common entry points are `subprocess.run()` (blocking, waits for the process to finish) and `subprocess.Popen()` (non-blocking, useful for streaming output). A critical mental model: always pass commands as a list of strings rather than a single string — this avoids shell injection vulnerabilities, which matter enormously in a security context. For example, `subprocess.run(['ping', '-c', '4', '8.8.8.8'], capture_output=True, text=True)` is safe; `subprocess.run('ping -c 4 8.8.8.8', shell=True)` is not recommended because it opens the door to injection if any part of the command comes from user input. The return object has `.stdout`, `.stderr`, and `.returncode` attributes. Writing output to a file then combines what you learned in file handling (open, write, close / context manager) and exception handling (FileNotFoundError, PermissionError, subprocess.TimeoutExpired) into one cohesive script. A common mistake is forgetting to decode bytes: always use `text=True` or decode manually. Another common mistake is not checking the return code, which means silently swallowing failures. Keep these points in mind as you build your script. --- **Workshop Brief** In this workshop you will build a self-contained Python script that performs a network reachability check using the `ping` command, captures its full output, and persists that output to a log file on disk.
