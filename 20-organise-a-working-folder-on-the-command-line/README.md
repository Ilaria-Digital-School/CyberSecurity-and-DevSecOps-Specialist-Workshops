# Organise a working folder on the command line

Theoretical Recap This workshop bridges your recent work with files, folders, and navigation to a critical professional skill: organising a logical, reproducible, and secure directory structure from the command line. A working folder in cybersecurity is not a random collection of files; it is a systematically organised hierarchy that supports the workflow of a test, investigation, or project. Key definitions are foundational. A directory tree is the hierarchical structure of folders branching from the root (`/`). A working directory is your current location (`pwd`). Relative paths specify locations from your current directory, while absolute paths start from the root. A mental model to adopt is that of a project scaffold: top-level folders for distinct phases, with subfolders for specific types of data or tools. A common mistake is creating flat, unstructured folders, leading to lost files and lost time. Another is using spaces in file or folder names, which complicates command-line operations. Always use underscores or hyphens instead. A mini example: for a pentest project, you might create `/home/user/projects/client_2024/` then subdirectories like `01_reconnaissance`, `02_scanning`, `03_exploitation`, each containing further folders for `tools`, `evidence`, and `reports`. This logical organisation ensures you know exactly where to save output from commands like `nmap`, where to store downloaded scripts, and where to write your final report.
